# Web 演示（只读）

把「审查报告 + 原文证据 + 评测结果」放在一页里的演示界面。
**不调用模型、不需要 API key、不需要 GPU** —— 所有内容来自仓库里已有的真实产物，打开就能看。

## 跑起来

```powershell
cd hetong
python -X utf8 webapp/server.py            # http://127.0.0.1:8077
```

依赖 `fastapi` + `uvicorn`（见 `requirements.txt` 的「Web 演示」段）。
若 `examples/` 为空，先跑 `python -X utf8 scripts/build_examples.py`。

## 三页分别看什么

| 页 | 内容 | 为什么值得看 |
|---|---|---|
| **审查报告** | 10 类条款清单 + 逐条的判定理由 / 缺口 / 证据；可按存在 / 缺失 / 高风险过滤 | 主功能。每条理由都以「我方=谁」开头 —— 立场从"隐式假设"变成了**可审计的输出** |
| **原文对照** | 合同全文，证据按字符位置高亮，点击高亮可回到对应条款；右侧是证据索引 | **位置是程序算的**，所以高亮不可能错位 —— 这是"证据没有编造"最直接的证明 |
| **评测** | 三个核心指标 + 逐类 F1 + 两项增强的前后对比 + 检索层指标 + **判错归因** | 展示的是"我知道它哪里错、错在哪一层"，而不只是"能跑"。归因表说明 31 个判错里真正的模型错只占 10% |

顶部还常驻一条「与金标准一致 9/10 · 1 处不一致」——**不挑全对的样例来展示**是刻意的：
这个项目的价值有一半在于"知道自己的边界在哪"。

## 架构与几个刻意的决定

- **服务端只做只读透传**：`examples/reports/*.json`、`examples/contracts/*.txt`、`eval/*.json`、
  `badcase_attribution.md`。**不造"演示专用数据"** —— 页面上的数字与 README、工程日志里的完全一致，可以互相追溯。
- **前端零框架、零构建**（原生 JS + 一个 CSS 文件，两个文件加起来 ~36KB）。要改样式只改 `static/styles.css`。
- **静态资源一律 `no-cache`（必须回服务器校验）**：否则改完 JS 浏览器还在用旧的缓存，
  看起来像"代码没生效"——这个坑本项目踩过一轮（`page.goto('...#eval')` 只是哈希变更，根本不重新加载页面）。
- **不做"实时审查"**：那会引入 API 花费与并发控制。演示要能离线、可复现、零成本。
  真要接，只需再包一个调用 `pipeline.review_contract` 的接口（E1 已经做完了并发与限流保护）。

## 设计约束（为什么它看起来不像"AI 生成"的通用模板）

| 维度 | 做法 |
|---|---|
| 配色 | 色相 ≤ 3（暖纸底 + 墨黑 + 一个深墨绿强调色）；风险色用**低饱和**版本；点缀面积 < 10% |
| 分隔 | **统一用 1px 细线**，不用阴影、不用色块分区；阴影只留给浮层 |
| 字体 | 衬线（合同原文 / 报告正文）+ 无衬线（界面标签 / 表格）两种；字重只用 400/500/600 |
| 间距 | 全程 8pt 网格（4/8/12/16/24/32/48/64） |
| 圆角 | 统一 4px（不出现 4 与 24 混用） |
| 动效 | 一条缓动曲线、220ms；`prefers-reduced-motion` 下全部关闭 |
| 明确不用 | 渐变、发光、emoji、图标包混用、彩虹配色、"了解更多"式空按钮 |

这些约束不是审美偏好，而是可对照的清单：**黑白稿测试**（去掉颜色后层级是否依然清楚）、
**眯眼测试**（视觉焦点是否唯一）、**5 秒测试**（5 秒内能否说出这是什么、下一步点什么）。
